# 옥수동 화덕피자 인터랙티브 랜딩 페이지 제작 명세

## 1. 작업 목표

옥수동 화덕피자의 메뉴를 보여주는 **단일 HTML 파일 기반 랜딩 페이지**를 제작한다.

페이지는 일반적인 카드형 메뉴 목록이 아니라, 사용자가 메뉴를 선택하면 **같은 테이블과 같은 배경에서 미녀 웨이트리스가 해당 피자를 가져와 내려놓는 8초짜리 영상**이 재생되고, 음식이 놓이는 시점에 맞춰 메뉴 정보 UI가 동적으로 등장하는 방식으로 구성한다.

다른 메뉴를 선택하면 현재 영상과 UI를 빠르게 되돌린 뒤, 새 메뉴 영상을 재생한다.

전체 결과물은 가능한 한 다음 파일 하나로 동작해야 한다.

```text
index.html
```

CSS와 JavaScript는 `index.html` 내부에 포함한다. 외부 프레임워크는 사용하지 않는다.

---

## 2. 에셋 구조

HTML 파일과 같은 폴더 또는 `assets` 폴더에 다음 파일들이 존재한다고 가정한다.

```text
pizza00.png

pizza01.png
pizza01.mp4

pizza02.png
pizza02.mp4

pizza03.png
pizza03.mp4

pizza04.png
pizza04.mp4

pizza05.png
pizza05.mp4

pizza06.png
pizza06.mp4
```

### 파일 의미

- `pizza00.png`
  - 아무 음식도 놓이지 않은 빈 테이블
  - 페이지의 초기 화면
  - 모든 메뉴 전환의 공통 원점

- `pizza01.png` ~ `pizza06.png`
  - 각 영상의 마지막 장면과 대응하는 정지 이미지
  - 영상 재생 완료 후 유지되는 화면
  - 영상 로딩 중 또는 영상이 끝났을 때 사용할 수 있음

- `pizza01.mp4` ~ `pizza06.mp4`
  - 빈 테이블에서 시작해 웨이트리스가 피자를 가져와 내려놓는 8초 영상
  - 영상의 시작 장면은 `pizza00.png`와 최대한 동일
  - 영상의 마지막 장면은 같은 번호의 PNG와 최대한 동일

에셋 경로는 코드 상단의 설정값 하나로 쉽게 변경할 수 있어야 한다.

```javascript
const ASSET_PATH = "./";
```

또는

```javascript
const ASSET_PATH = "./assets/";
```

## 3. 기본 화면 구성

화면 전체를 채우는 풀스크린 랜딩 페이지로 만든다.

### 배경

- 처음에는 `pizza00.png`를 화면 전체 배경으로 표시
- 이미지 비율은 유지하되 화면을 꽉 채우도록 처리
- `object-fit: cover`
- 화면 중앙을 기준으로 배치
- 모바일과 데스크톱 모두 대응
- 배경이 전환될 때 화면이 흔들리거나 크기가 달라 보이지 않아야 함

### 메뉴 선택 영역

화면 가장자리 또는 하단에 메뉴 선택 버튼 6개를 배치한다.

예시:

```text
01  02  03  04  05  06
```

또는 메뉴 이름을 사용할 수 있도록 데이터 구조로 분리한다.

버튼은 배경을 가리지 않도록 반투명하게 표시한다.

현재 선택된 메뉴는 명확하게 표시한다.

모바일에서는 가로 스크롤이 가능해야 한다.

## 4. 핵심 동작

### 초기 상태

```text
pizza00.png
```

빈 테이블을 보여주며 메뉴 선택을 기다린다.

초기 상태에서는 상세 메뉴 UI를 표시하지 않는다.

### 메뉴 선택

사용자가 메뉴 버튼을 선택하면 다음 순서로 동작한다.

```text
빈 테이블
→ 선택한 pizzaXX.mp4 재생
→ 영상 후반부에 UI 등장
→ 영상 마지막 프레임에서 정지
→ pizzaXX.png 상태로 유지
```

영상은 기본적으로 다음 속도로 재생한다.

```javascript
playbackRate = 1.75;
```

8초 영상은 약 4.57초 동안 재생된다.

### 다른 메뉴 선택

현재 메뉴가 화면에 표시된 상태에서 다른 메뉴를 누르면 다음 순서로 동작한다.

```text
현재 메뉴 UI 빠르게 퇴장
→ 현재 영상을 빠르게 역방향처럼 되돌림
→ 빈 테이블 화면 도착
→ 새 메뉴 영상 정방향 재생
→ 새 메뉴 UI 등장
```

브라우저의 음수 `playbackRate`는 사용하지 않는다.

현재 MP4를 JavaScript로 직접 역재생하는 방식 대신, `currentTime`을 짧은 간격으로 감소시키는 방식으로 구현한다.

예시 개념:

```javascript
currentTime -= delta * reverseSpeed;
```

역방향 전환은 매우 빠르게 처리한다.

권장 속도:

```javascript
reverseSpeed = 3.5;
```

목표 체감 시간:

```text
약 1.0초 ~ 1.8초
```

역재생 중에는 오디오를 끈다.

빈 테이블에 도착하면 비디오를 숨기고 `pizza00.png`를 표시한 뒤 새 메뉴 영상을 시작한다.

## 5. 재생 상태 관리

상태를 명확하게 관리한다.

```javascript
const State = {
  IDLE: "idle",
  ENTERING: "entering",
  VIEWING: "viewing",
  LEAVING: "leaving"
};
```

### 상태 의미

- `IDLE`
  - 빈 테이블
  - 메뉴 선택 가능

- `ENTERING`
  - 새 메뉴 영상 정방향 재생 중

- `VIEWING`
  - 영상이 끝나고 해당 메뉴의 정지 화면과 UI가 보이는 상태

- `LEAVING`
  - 현재 메뉴 UI가 사라지고 영상이 빠르게 되감기는 상태

### 연속 클릭 처리

영상 재생 중 다른 메뉴를 누를 수 있다.

이 경우 현재 동작이 끝날 때까지 모든 클릭을 큐에 쌓지 않는다.

마지막으로 누른 메뉴만 기억한다.

```javascript
pendingMenuId
```

예시:

```text
01 재생 중
→ 03 클릭
→ 05 클릭
→ 02 클릭
```

최종적으로 `02`만 실행한다.

같은 메뉴를 다시 누르면 아무 동작도 하지 않는다.

## 6. 영상과 이미지 전환

HTML 구조는 배경 이미지와 비디오를 같은 위치에 겹쳐 배치한다.

```html
<div class="stage">
  <img id="stageImage">
  <video id="stageVideo"></video>
</div>
```

두 요소는 정확히 같은 크기와 위치를 가져야 한다.

```css
.stage img,
.stage video {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

### 재생 시작

1. `pizza00.png` 표시
2. 선택한 MP4를 미리 로드
3. 비디오의 첫 프레임이 준비되면 이미지 위에 비디오 표시
4. `playbackRate = 1.75`
5. 재생 시작

### 재생 종료

1. 영상 마지막 프레임에서 일시정지
2. 대응하는 `pizzaXX.png`를 뒤에 준비
3. 이미지가 준비되면 비디오를 숨기거나 마지막 프레임 상태 유지
4. 화면이 튀지 않도록 부드럽게 전환

가능하면 영상 마지막 프레임을 그대로 유지한다.

PNG와 영상 마지막 프레임 사이에 미세한 차이가 있다면 영상 프레임을 유지하는 편을 우선한다.

## 7. 메뉴 정보 UI

UI는 처음부터 표시하지 않는다.

피자가 테이블에 가까워지거나 내려놓는 시점부터 등장해야 한다.

8초 원본 영상을 1.75배속으로 재생하므로, 실제 재생 시간 약 4.57초를 기준으로 한다.

권장 등장 시점:

```text
재생 진행률 65%부터 시작
재생 진행률 85%에서 주요 UI 완성
```

예시:

```javascript
const progress = video.currentTime / video.duration;
```

### UI 구성 예시

```text
메뉴 번호
메뉴 이름
한 줄 소개
핵심 재료 또는 특징 3개
스토리 또는 설명
상세 보기 버튼
매장 보기 버튼
```

단, 화면을 과도하게 가리지 않는다.

음식과 웨이트리스가 중심이 되어야 한다.

### UI 애니메이션

단순한 페이드인만 사용하지 않는다.

음식이 놓이는 순간과 연결된 느낌으로 연출한다.

예시:

- 제목이 아래에서 살짝 올라옴
- 재료 키워드가 순차적으로 나타남
- 얇은 라인이 접시 주변에서 펼쳐짐
- 작은 원형 또는 불꽃 모티프가 퍼짐
- 설명 패널이 좌우에서 부드럽게 열림
- 버튼은 마지막에 활성화

과도한 파티클 효과는 피한다.

UI는 애니메이션이 끝나면 안정된 상태로 유지한다.

## 8. UI 배치

데스크톱 권장 배치:

```text
왼쪽 또는 오른쪽 하단:
메뉴 이름, 설명, 특징

하단 중앙:
메뉴 선택 버튼

상단:
브랜드명 또는 로고
```

모바일 권장 배치:

```text
상단:
브랜드명

하단:
메뉴 정보 패널

가장 아래:
가로 스크롤 메뉴 버튼
```

모바일에서는 UI가 피자를 완전히 가리지 않도록 높이를 제한한다.

필요하면 정보 패널을 접거나 펼칠 수 있게 한다.

## 9. 메뉴 데이터 구조

메뉴 정보는 HTML에 직접 반복 작성하지 말고 JavaScript 데이터로 관리한다.

예시:

```javascript
const menus = [
  {
    id: 1,
    title: "Menu 01",
    subtitle: "Wood-fired Pizza",
    description: "메뉴 설명을 입력하세요.",
    tags: ["48시간 숙성", "화덕", "수제 도우"],
    image: "pizza01.png",
    video: "pizza01.mp4"
  },
  {
    id: 2,
    title: "Menu 02",
    subtitle: "Wood-fired Pizza",
    description: "메뉴 설명을 입력하세요.",
    tags: ["버섯", "치즈", "화덕"],
    image: "pizza02.png",
    video: "pizza02.mp4"
  }
];
```

6개 메뉴까지 작성한다.

이후 메뉴 이름이나 설명을 쉽게 수정할 수 있어야 한다.

## 10. 오디오

영상에 오디오가 포함되어 있더라도 기본값은 음소거로 시작한다.

```javascript
video.muted = true;
```

브라우저 자동재생 정책에 대응하기 위해 반드시 음소거 상태로 재생한다.

선택적으로 화면 한쪽에 음소거 해제 버튼을 둘 수 있다.

역방향 전환 중에는 항상 음소거한다.

---

## 11. 로딩 처리

모든 영상을 한 번에 다운로드하지 않는다.

초기에는 다음만 우선 로드한다.

```text
pizza00.png
첫 번째 메뉴의 poster 이미지
```

사용자가 메뉴를 선택할 때 해당 영상을 로드한다.

한 번 재생한 영상은 브라우저 캐시에 남도록 한다.

선택적으로 페이지 로드 후 유휴 시간에 영상을 순차적으로 프리로드한다.

```javascript
requestIdleCallback
```

지원하지 않는 브라우저에서는 `setTimeout`으로 대체한다.

영상 로딩이 오래 걸리면 작고 절제된 로딩 표시를 제공한다.

## 12. 반응형 및 접근성

- 데스크톱, 태블릿, 모바일 지원
- 세로 화면과 가로 화면 모두 대응
- 메뉴 버튼은 키보드로 선택 가능
- `aria-label` 제공
- 포커스 표시 유지
- `prefers-reduced-motion` 대응

사용자가 동작 줄이기 설정을 사용하면:

```text
영상 전환 대신
pizza00.png → pizzaXX.png
짧은 페이드 전환
```

으로 처리한다.

## 13. 성능 요구사항

- 외부 UI 프레임워크 사용 금지
- 외부 애니메이션 라이브러리 사용 금지
- 순수 HTML, CSS, JavaScript
- 가능한 한 단일 HTML 파일
- 모바일에서 부드럽게 동작
- 영상과 이미지 요소는 한 세트만 재사용
- 메뉴마다 `<video>`를 여러 개 생성하지 않음
- 화면 크기 변경 시 레이아웃 깨짐 방지
- 메모리 누수 방지
- 이벤트 리스너 중복 등록 금지

---

## 14. 디자인 방향

- 따뜻한 오렌지와 브라운 계열
- 애니메이션 스타일 레스토랑 이미지와 조화
- 고급스럽지만 지나치게 무겁지 않음
- 음식과 웨이트리스가 가장 먼저 보이도록 함
- UI는 반투명한 유리 또는 얇은 패널 느낌
- 둥근 카드 남발 금지
- 큰 텍스트와 긴 설명으로 화면을 가리지 않음
- 랜딩 페이지 전체가 하나의 짧은 인터랙티브 애니메이션처럼 느껴져야 함

## 15. 핵심 사용자 흐름

```text
1. 페이지 진입
2. 빈 테이블 pizza00.png 표시
3. 메뉴 선택
4. 선택한 pizzaXX.mp4를 1.75배속으로 재생
5. 영상 후반부에 UI 애니메이션 시작
6. 영상 종료 후 해당 메뉴 화면 유지
7. 다른 메뉴 선택
8. UI 빠르게 퇴장
9. 현재 영상을 빠르게 되감아 빈 테이블로 복귀
10. 새 메뉴 영상 재생
11. 새 UI 등장
```

## 16. 구현 시 주의사항

1. 배경 위치와 크기가 메뉴마다 달라 보이면 안 된다.
2. 이미지와 영상이 교체될 때 화면이 한 프레임이라도 검게 깜빡이면 안 된다.
3. 새 메뉴를 누를 때 이전 UI가 남아 있으면 안 된다.
4. 빠르게 여러 메뉴를 눌러도 상태가 꼬이면 안 된다.
5. 역방향 이동 중 새 메뉴를 누르면 마지막 선택만 반영한다.
6. 영상 재생 실패 시 대응 PNG를 표시한다.
7. 재생 종료 이벤트만 믿지 말고 `timeupdate`와 `ended`를 함께 처리한다.
8. 모바일 Safari에서도 동작하도록 `playsinline`을 사용한다.

```html
<video playsinline muted preload="metadata"></video>
```

9. 페이지 첫 화면에 불필요한 소개 문구나 팝업을 띄우지 않는다.
10. 결과물은 바로 브라우저에서 열어 테스트할 수 있어야 한다.

## 17. 최종 산출물

다음 파일을 작성한다.

```text
index.html
```

필요하다면 추가로 다음 파일을 만들어도 된다.

```text
README.md
```

하지만 핵심 기능은 `index.html` 하나만으로 동작해야 한다.

코드는 읽기 쉽게 작성하고, 주요 상태 전환과 영상 제어 부분에 한글 주석을 추가한다.

임시 이미지, 임시 영상, 외부 URL, Base64 데이터는 사용하지 않는다.

실제 로컬 파일명을 그대로 사용한다.

```text
pizza00.png
pizza01.png ~ pizza06.png
pizza01.mp4 ~ pizza06.mp4
```
