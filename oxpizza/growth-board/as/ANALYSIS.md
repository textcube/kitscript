- 로얄맨션은 연령대별 메인 캠페인을 분리했다.
- 복수 소재와 제외 검색어를 사용한다.
- 스마트플레이스 AI 리뷰 답글을 실제 운영에 적용했다.

### 입증이 부족한 부분

- 세 계정 통합 성과 보고
- 전화·길찾기·예약·방문·매출 전환 측정
- 예산 조기 소진을 줄이기 위한 지속 조정

- AI 리뷰 답글의 지점별 사람 검수
- 변경 이력에서 확인되는 사람의 분석·판단 작업

- 광교 메인 예산 일부를 중위·하위로 이동해 비교한다.

### 4주차: 계약과 역할 판단

- 반복 실행, 시스템 생성, 사람의 판단 업무를 분리한다.
- 절감 시간, 광고비, 오류율, 전환 행동을 비교한다.
- 외주 유지·혼합 운영·직접 운영 중 하나를 결정한다.
- 외주를 유지한다면 성과 책임과 작업 로그 제출 범위를 계약에 명시한다.

9. 개선안 생성과 재집행 승인

### 자동 실행에 적합한 업무

- 사진의 흔들림·노출·중복·구도·메뉴 인식
- 파일 분류와 사진 권한 정보 연결
- 썸네일 후보와 규격별 이미지 생성
- 16자 제한, 금칙어, 오탈자 검사
- 성과 데이터 수집과 주간 보고서
- 비효율과 예산 조기 소진 경보

### 반자동화가 적합한 업무

- 광고 문안과 소재 조합
- 등록 대기열과 대량등록 자료 생성
- A/B 실험군과 중단 후보 추천
- 제외 검색어 추가·해제 후보
- 승자 소재의 플랫폼별 재가공

### 사람의 최종 결정이 필요한 업무

- 실제 광고 등록과 예산 증액
- 가격·할인·법적 표현 승인
- 인물 사진·초상권·음원·원본 사용 권한
- 표본이 부족한 승자 판정
- 브랜드 방향, 고객 불만, 위기 대응

### 플랫폼 등록 원칙

- 공식 API, 예약 게시, 대량등록 기능을 우선한다.
- 지원하지 않는 기능은 관리자 승인 대기열로 처리한다.
- 화면 좌표를 흉내 내는 자동 클릭은 UI 변경과 계정 사고 위험이 있어 최후 수단이다.
- 등록 실패, 중복, 인증, 권한 오류가 발생하면 자동화를 중단하고 진단 기록을 남긴다.

## 11. 진단 기록과 관찰 가능성

모든 자동화 실행은 하나의 실행 번호로 다음 자료를 연결해야 한다.

### 주요 화면 스크린샷

- 등록 전후
- 승인 화면
- 오류 메시지
- 예산과 성과표
- 자동 마스킹된 계정·개인정보

### 구조화 텍스트 로그

- 실행 번호
- 시간
- 계정과 지점
- 입력 자료와 설정값
- 생성 결과
- 비용
- 오류 코드와 메시지
- 승인자
- 수정 이유
- 이전 버전과 차이

### 영상 캡처

- 정상 실행 전체를 상시 녹화하지 않는다.
- 오류 전후, 복잡한 등록, 재현이 어려운 UI 상태만 짧게 캡처한다.
- 영상의 시작·종료 시각을 텍스트 로그와 연결한다.

### 보존 원칙

- 정상 실행: 요약 스크린샷과 텍스트 로그
- 오류 실행: 오류 전후 스크린샷과 짧은 영상
- 예산 변경: 승인 화면 필수
- 원본 사진: 파일 해시로 파생본과 연결
- 삭제·보존 기간은 계정정보와 고객정보의 민감도에 따라 별도로 정한다.

핵심 원칙:

> 기록이 없으면 자동화는 빨라진 수작업이고, 기록이 남으면 개선 가능한 운영 시스템이 된다.

## 17. 주의할 해석

- 전환 0건을 매출 0원으로 해석하지 않는다.
- 클릭률이 높다고 좋은 고객을 확보했다고 단정하지 않는다.
- 자동 변경 이력이 많다고 사람이 많이 관리했다고 해석하지 않는다.
- 변경 이력이 없다고 반드시 방치라고 단정하지 않는다. 외부 작업 또는 표시 문제가 있을 수 있다.
- 로얄맨션 광고그룹 미표시를 삭제로 단정하지 않는다.
- AI 답글의 동일 시각 등록을 대행사의 기만으로 단정하지 않는다. 일괄 승인 또는 플랫폼 기능일 수 있다.
- 자동화 가능성과 플랫폼이 공식 허용하는 등록 권한은 별개다.
- 상품화 판단은 내부 6개 지점에서 시간·품질·성과·오류율이 검증된 뒤 내려야 한다.

## 18. 한 문장 결론

> 광고를 대신 실행하는 데서 끝나지 않고, 광고·숏폼·블로그·리뷰 운영을 기록 가능한 반복 루프로 만들며, 6개 지점에서 검증된 운영체계 자체를 외식 브랜드용 솔루션으로 상품화한다.
